    Plugins¶

    FreeXmlToolkit can be extended with plugins: jar files that add an activity with its own side panel, menu items, validation checks, tasks at start and reactions to opened documents. The FundsXML extension is built as such a plugin and serves as the reference implementation.

    Plugins are programs

    A plugin runs inside FreeXmlToolkit with the same rights as the application: it can read and write your files and reach the network. Install plugins only from sources you trust. Administrators can switch external plugins off (see Administration).

    Installing a plugin¶

    1. Open Settings → Extensions → PLUGINS and click Open Plugins Folder (~/.freeXmlToolkit/plugins, on Windows %USERPROFILE%\.freeXmlToolkit\plugins).
    2. Copy the plugin's .jar file into that folder.
    3. Restart FreeXmlToolkit.

    The PLUGINS card lists every plugin found at start — built-in ones and the jars in the folder — with its version and description. Untick a plugin and save the settings to switch it off; this takes effect at the next start. A plugin that could not be loaded is listed with the reason (e.g. a jar without plugin, or an error while it registered); the others still load.

    What a plugin can contribute¶

    Contribution Where it appears
    Activity A button in the Activity Bar (above Settings) and an entry in View → Activities; its side panel is created the first time it is shown. A plugin can hide the activity while it is not in use (FundsXML: while the extension is off).
    Menu item At the end of the Tools menu, or in the Help menu (also in the header's Help popup)
    Validator Its problems appear with every XML validation — the Validation panel, F8, and fxt-cli validate — with the validator's name as source
    Startup task Runs once in the background a few seconds after start (FundsXML: checks for new schema versions)
    Document listener Is told when a document has been opened; it can show a bar above the editor (FundsXML: the hint bar)
    Stylesheet Added to the window, for the plugin's own panels
    Schema A Schema Library entry (source Plugin) while the plugin is on; never saved to the user's library

    Application services — settings, favorites, XPath snippets, templates, the Schema Library — are available to a plugin through PluginContext.service(…).

    Writing a plugin¶

    A plugin is a class implementing org.fxt.freexmltoolkit.plugin.FxtPlugin, listed in META-INF/services/org.fxt.freexmltoolkit.plugin.FxtPlugin of its jar. The full guide — how plugins are loaded, every contribution type, threads, translations, building, testing and debugging — is Writing Plugins; a complete example project is in examples/plugin-sample.

    Built-in plugins¶

    Plugin On by default
    FundsXML yes (its activity appears once the extension is enabled) FundsXML Extensions
    ISO 20022 Payments (SEPA) no ISO 20022 Payments
    ebInterface (Austrian e-invoice) no ebInterface
    FinDatEx Templates (EMT, EET, EPT, TPT) no FinDatEx Templates
    XBRL (with Arelle) no XBRL

    A plugin can say it is off until the user switches it on (enabledByDefault()), and it can add XML Schemas to the Schema Library (context.addSchema(new PluginSchema(namespace, url, description, null))).

    Updating plugins¶

    Plugins have no update channel of their own. What keeps each part current:

    Part How it stays current
    Built-in plugins (FundsXML, ISO 20022, ebInterface, FinDatEx, XBRL) and their data (FinDatEx field definitions, ISO 20022 schemas) With the application: Help → Check for Updates… or the automatic update check, see Installation
    FundsXML schemas, samples, Schematron rules and snippets In addition, the FundsXML plugin checks GitHub once a day and installs a new release in the background, see FundsXML Extensions (fundsxml.update.check.enabled=false turns it off)
    Plugins from the plugins folder (.jar) By hand: put the new jar into the folder, remove the old one, restart. Settings → Extensions → PLUGINS shows the version that is loaded.
    Arelle (used by the XBRL plugin) It is a separate program: pip install -U arelle-release

    With the policy update.allowed=false, application updates, and with them the built-in plugins and their data, arrive only through your software distribution. The FundsXML content check is not affected by this policy; switch it off with fundsxml.update.check.enabled=false, or switch the plugin off with plugin.fundsxml.enabled=false.

    The FundsXML plugin¶

    FundsXmlPlugin (built in, in controls/shell/editor/) is the reference: it contributes the FundsXML activity (visible while the extension is enabled), the FundsXML Website and FundsXML Schema Docs Help items, the startup task that keeps the schema content up to date, and a document listener that offers the extension once when a FundsXML document is opened. Switching the plugin off in Settings → PLUGINS removes all of these.

    Administration¶

    Key (in policy.properties) Effect
    plugins.external.allowed=false No plugins are loaded from the plugins folder; built-in ones still load
    plugin.<id>.enabled=false The plugin is not loaded and cannot be switched on (e.g. plugin.fundsxml.enabled=false)

    The plugins folder can be moved with the Java option -Dfxt.plugins.dir=<folder> (or fxt.plugins.dir in policy.properties / defaults.properties), for example to a read-only folder that software distribution fills. See Administration & Policies.

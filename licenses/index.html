    Third-Party Libraries and Licenses¶

    FreeXmlToolkit itself is licensed under the Apache License 2.0. It is built on third-party libraries and ships with its own Java runtime. The tables below list the libraries the project uses directly; the SBOM of each release lists every library in the installation, including the ones these pull in. Two parts need more than a table row: the Xerces build for XSD 1.1 and the bundled Java runtime with JavaFX. This page explains the license situation; it is not legal advice.

    License Texts in the Installation¶

    Every library jar carries its own license and notice files (META-INF/), in the installation's app folder. The Java runtime keeps its license texts in a legal folder, one subfolder per module:

    Installation Java runtime license texts
    Windows runtime\legal\ in the installation folder
    macOS FreeXmlToolkit.app/Contents/runtime/Contents/Home/legal/
    Linux .deb / .rpm /opt/freexmltoolkit/lib/runtime/legal/
    Linux ZIP lib/runtime/legal/ in the extracted folder

    Software Bill of Materials (SBOM)¶

    From version 2.11 on, every GitHub release carries a machine-readable SBOM in the CycloneDX 1.6 format: FreeXmlToolkit-<version>-sbom.cdx.json and FreeXmlToolkit-<version>-sbom.cdx.xml. It lists every library the application ships (the runtime classpath, not test or build tools) with its version, license, package URL and hashes, and it is covered by the release's SHA256SUMS.txt. Security and compliance tools such as Dependency-Track, Trivy or Grype read it directly.

    To create it from the sources: ./gradlew cyclonedxDirectBom writes build/reports/cyclonedx-direct/bom.json and bom.xml.

    Why a Xerces from eXist-db. XSD 1.1 validation (assertions, conditional types, open content) comes from Apache Xerces-J. The Apache project builds Xerces-J 2.12.2 in two variants: the XSD 1.0 build, which is the one on Maven Central as xerces:xercesImpl, and the XSD 1.1 build, which Apache only offers as a download on xerces.apache.org. The eXist-db project publishes the XSD 1.1 build to Maven Central under its own group id org.exist-db.thirdparty.xerces, so that build tools can use it. FreeXmlToolkit uses that artifact:

    • It is Apache code under the Apache License 2.0, not an eXist-db product under eXist-db's license (LGPL). The jar reports itself as Xerces-J 2.12.2-xml-schema-1.1 from the Apache Software Foundation and contains Apache's LICENSE and NOTICE. "Fork" only means a different place of publication.
    • The matching sources are on Maven Central next to the jar (xercesImpl-2.12.2-xml-schema-1.1-sources.jar); the Apache sources are the release tag Xerces-J_2_12_2 in the Apache Xerces repository.
    • For assertions, Xerces needs the XPath 2.0 processor from the Eclipse Web Tools Platform and the CUP parser runtime. eXist-db publishes both in the same way. The XPath 2.0 processor is under the Eclipse Public License 1.0 (a weak copyleft for the library itself, without effect on FreeXmlToolkit's code); it is distributed unchanged, and its sources are on Maven Central (xpath2-1.2.0-sources.jar).
    • Xerces depends on the old XML Commons interface jars (xml-apis), and the Xerces jar contains copies of them. They are inert on Java 25: the classes of the javax.xml, org.w3c.dom and org.xml.sax packages always come from the Java runtime's own java.xml module.
    • The XSD 1.1 build is used for XSD 1.0 schemas as well unless Settings → Schemas & Validation → XML parser is set to Saxon; XSD 1.1 schemas always use it.

    Bundled Java Runtime and JavaFX¶

    FreeXmlToolkit does not need an installed Java. Each installer and ZIP contains a Java 25 runtime, made with jlink from the BellSoft Liberica Full JDK. "Full" means the JDK includes OpenJFX (JavaFX), the UI toolkit; FreeXmlToolkit does not download or ship JavaFX jars of its own.

    • What is in it. Only the modules the application needs (java.base, java.desktop, java.xml, java.net.http, …, and javafx.base, javafx.controls, javafx.fxml, javafx.graphics, javafx.media, javafx.swing, javafx.web). The modules are not modified; jlink only leaves out the other modules, debug information and the command line tools. The release file in the runtime folder names the exact version.
    • License. OpenJDK and OpenJFX are under the GNU General Public License version 2 with the Classpath Exception. The Classpath Exception allows an application to run on and link with the runtime under its own license; FreeXmlToolkit's code stays under the Apache License 2.0, and the runtime stays under GPLv2+CE. Some native parts carry their own licenses: WebKit in javafx.web (used for the HTML preview and the help pages) and GStreamer/GLib in javafx.media are mostly under the LGPL 2.1, and libraries such as ICU, libxml2, libxslt, FreeType, HarfBuzz, libjpeg and libpng under permissive licenses. Every one of them is listed with its full license text in the module's legal subfolder (see License Texts in the Installation).
    • Sources. The runtime is the unmodified Liberica build. Its sources are published by BellSoft (Liberica source packages, github.com/bell-sw) and by the OpenJDK projects (openjdk/jdk, openjdk/jfx).
    • Updates. The runtime is replaced with every FreeXmlToolkit release, which picks up the latest Liberica 25 update at build time. Java security fixes therefore arrive with FreeXmlToolkit updates, not through a separately installed Java.
    • The TestFX/Monocle jar in the test dependencies below is only used to run the tests headless; it is not part of the installation.

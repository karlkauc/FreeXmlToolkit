Transformieren

XSLT, XQuery und XPath

XSLT 3.0, XPath 3.1 und XQuery 3.1 laufen auf Saxon HE, das Ergebnis erscheint unter dem Editor.

  • Parameter, Ausgabemethode und eine Live-Vorschau
  • Szenarien halten Stylesheet, Eingabe und Parameter zusammen
  • Stapeltransformation vieler Dateien
  • XSLT 1.0 und 2.0, wenn ein Stylesheet kompatibel bleiben muss
Zur Dokumentation (englisch)
Abfragekonsole

Das offene Dokument befragen

Einen XPath-, XQuery- oder JSONPath-Ausdruck eingeben und das Ergebnis sofort sehen.

  • Läuft gegen das Dokument im Editor
  • Ein Zeitlimit stoppt eine Abfrage, die aus dem Ruder läuft
  • Optional: mit dem KI-Assistenten aus einer Frage eine Abfrage machen
Zur Dokumentation (englisch)
Debugger

XSLT, XQuery und Schematron schrittweise

Anhalten, wo es zählt, und Kontextknoten, Variablen und die bisher geschriebene Ausgabe ansehen.

  • Bedingte Haltepunkte, Trefferzähler und Logpoints
  • Überwachungen, Aufrufliste, Inline-Werte und ein Wertefenster mit XPath
  • Anhalten bei Fehlern, bei Meldungen oder wenn ein Eingabeknoten verarbeitet wird
  • Abdeckung und „Explain Match“ für die Template-Regel, die gewonnen hat
Zur Dokumentation (englisch)
Profiler

Das langsame Template finden

Ein Profillauf misst jedes Template und jede Funktion eines Stylesheets oder einer Abfrage.

  • Gesamt- und Eigenzeit, Aufrufbaum und Flame Graph
  • Für XSLT und XQuery
  • Von der Kommandozeile mit transform --profile
Zur Dokumentation (englisch)
Tests

Mit XSpec testen

XSpec-Tests für XSLT, XQuery und Schematron ausführen und sehen, welche Erwartungen fehlgeschlagen sind.

  • Aus dem Editor oder mit fxt-cli xspec
  • Szenario-Prüfungen vergleichen ein Transformationsergebnis mit einer erwarteten Datei
Zur Dokumentation (englisch)
Pipelines

XProc-3.0-Pipelines

Pipelines laufen auf XML Calabash 3.

  • Standardmäßig eingeschränkt: keine Programme, kein Netzwerk
  • „Run Pipeline“ auf jedem .xpl-Dokument, das Ergebnis im Ausgabebereich

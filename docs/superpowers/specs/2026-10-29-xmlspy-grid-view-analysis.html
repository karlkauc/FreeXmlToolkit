Das XML-Grid von XMLSpy: Features und Optik

Was die Grid-Ansicht (Grid View) kann, wie sie aussieht und welche Teile im FreeXmlToolkit-Grid schon vorhanden sind. Grundlage sind das Altova-Handbuch (DE/EN), die Produktseite und der Blog zur Neuentwicklung des Grids in Version 2021r2.

1. Überblick und Grundaufbau

Quelle: Grid-Ansicht (DE), Document Display (EN), Screenshot Gesamtansicht

Die Grid-Ansicht zeigt ein XML-Dokument als Hierarchie verschachtelter Container. Jede Zeile ist ein Knoten. Links steht die Namenszelle mit Typ-Icon und fettem Knotennamen, rechts entweder die Wertzelle oder der eingerückte Container mit den Kindern. Die Ansicht gibt es für XML, JSON, YAML und DTD; Altova hat sie mit Version 2021r2 (März 2021) komplett neu geschrieben.

  • Raster: hellgraue Hairlines, weißer Hintergrund, keine Zebra-Streifen. Jede Einrückungsebene ist ein eigener Rahmen, der links an der Namenszelle des Elternelements „andockt“.
  • Namenszelle: fester Platz für Typ-Icon, Name, Zähler, darunter das Tabellen-Icon. Die Breite ist pro Spalte ziehbar (siehe Abschnitt 4).
  • Werte: normale Schrift, linksbündig, bei Word-Wrap mehrzeilig. Die Zellhöhe folgt dem Inhalt.
  • Selektion/Fokus: hellblaue Fläche mit blauem Rand (Farben konfigurierbar, inkl. inaktiver Variante wenn ein anderes Fenster aktiv ist).
  • Validierungsfehler (Validate on Edit): Wert in Rot, rotes !-Icon, daneben eine Glühbirne für SmartFix-Vorschläge, Tooltip mit Fehlertext.
  • Suchtreffer (Ctrl+F/Ctrl+H) werden orange hinterlegt, inklusive der umgebenden Zelle.

2. Knotentypen und Darstellung von Werten und Attributen

Quelle: Document Content, Screenshot Typ-Dropdown

Jede Grid-Zeile ist genau ein Knoten. Das Typ-Icon oben links in der Zelle ist zugleich ein Dropdown zum Typwechsel: ein Klick öffnet die Liste aller Typen, der Knoten wird konvertiert und behält, soweit möglich, Name und Wert.

Regeln für Werte und Attribute

  • Attribute zuerst: unter einem Element stehen immer erst alle Attribute, dann Kind-Elemente und Text. Ein Typwechsel Element → Attribut sortiert den Knoten deshalb nach oben.
  • Einfacher Inhalt steht direkt in der Wertzelle rechts vom Namen (City | Dallas). Es gibt keine eigene Textzeile für den Inhalt eines Blattelements.
  • Gemischter Inhalt (mixed content) wird als Folge von Text- und Elementzeilen dargestellt; aufeinanderfolgende Textknoten werden beim Typwechsel automatisch zusammengelegt.
  • Namespaces: xmlns-Deklarationen sind normale Attributzeilen; Präfixe werden rot vom lokalen Namen abgesetzt.
  • Entities werden aufgelöst angezeigt, optional als Rohtext (Einstellung „Convert XML entities to raw text on loading“). „Edit as Raw Text“ (Ctrl+Alt+R) macht aus dem gesamten Inhalt einer Elternzelle eine einzige Rohtext-Zelle mit unaufgelöstem Markup.
  • Whitespace ist sichtbar schaltbar: Leerzeichen als Mittelpunkt, Tab als Pfeil, Zeilenende als sichtbarer Umbruch in der Zelle.
  • Bilder: Base64-Inhalt (PNG, JPEG, BMP, animiertes GIF) wird direkt als Grafik in der Zelle gerendert; SVG wird als XML aufgeklappt und zusätzlich unter dem letzten Kind von svg als Bild gezeigt.
  • Textrichtung pro Textknoten umschaltbar (LTR/RTL) über das Kontextmenü.

5. Tabellenansicht (Table Display) für wiederholte Elemente

Quelle: Table Display (XML), Display as Table, Flip Rows/Columns, Sort, Tutorial „Editing in Table Display“, Screenshots Standard / Tabelle / sortiert mit Fehler

Aktivieren

  • Voraussetzung: eine Folge gleichnamiger Geschwisterelemente (auch ein Einzelelement ist möglich; sein Tabellen-Icon erscheint beim Anklicken).
  • Toggle über das Tabellen-Icon unter dem Namen der ersten Instanz, über XML › Display as Table oder das Toolbar-Icon. Aktiv = Icon farbig.
  • Einstellung „Detect tables automatically on loading“ (XML: an, Schwelle 0 % gefüllte Zellen; JSON: an, 65 %): Wiederholungen werden beim Laden direkt als Tabelle gezeigt, wenn genug Zellen belegt sind.
  • Der Zustand ist pro Wiederholungsgruppe; Standard- und Tabellendarstellung können im selben Dokument gemischt sein.

Aufbau der Tabelle

  • Spalten = Kindknoten der Wiederholung, in Dokumentreihenfolge; Attribute zuerst (Icon =), dann Kind-Elemente (<>), auch Textinhalt. Spaltenkopf = Typ-Icon + Name.
  • Zeilen = Instanzen, mit Zeilennummer in einer gelben Nummernspalte (die Nummern existieren nur in der Anzeige).
  • Fehlende Knoten ergeben leere Zellen; ihre Farbe („Missing Table Entry“) ist konfigurierbar.
  • Komplexe Kinder: enthält eine Zelle wieder Kinder, erscheint darin ein verschachtelter Container oder eine verschachtelte Tabelle, jeweils mit eigener Pfeilspitze.
  • Formelspalten: haben alle Zellen einer Spalte dieselbe Formel, steht sie einmal im Kopf (f(x)), die Zellen zeigen nur ihr Ergebnis mit #-Icon.

Zeilen und Spalten tauschen (Flip)

Die Zelle oben links trägt das Flip-Icon. Ist sie markiert, wird XML › Flip Rows/Columns (Toolbar-Icon) aktiv und die Tabelle wird transponiert: die Kindknoten werden Zeilen, die Instanzen Spalten. Altova empfiehlt das für breite Tabellen mit wenigen Zeilen. Auch im geflippten Zustand bleiben Sortieren, Bearbeiten und Einfügen verfügbar; der Toggle gilt pro Tabelle.

Operationen auf ganzen Zeilen und Spalten

Objekte und Arrays, die mindestens ein Objekt oder Array enthalten, lassen sich einzeln als Liste oder Tabelle anzeigen (Icon unter dem Objekt/Array-Icon). Array-Elemente werden Zeilen, die Property-Namen Spalten; Datentypen werden automatisch erkannt und per Kürzel (* Auto, " String, [ Array, { Objekt, // Kommentar, = Formel) überschrieben.

6. Bearbeiten von Struktur und Inhalt

Quelle: Document Structure, Document Content, Entry Helpers, Screenshot Eingabehilfen

Inhalt

  • In-Place-Edit: Doppelklick in die Wertzelle (oder Namenszelle), Enter bestätigt, Esc verwirft. Ctrl+Enter fügt in Ausdrücken einen Zeilenumbruch ein.
  • Autocomplete bei zugewiesenem Schema: Popup an der Zelle plus Eingabehilfen; Pfeiltasten wählen, Enter übernimmt. Boolean/Enumerationen als Dropdown.
  • Validate on Edit (Default aus): Wohlgeformtheit und Schema-Validierung bei jeder Eingabe, Fehler rot mit SmartFix-Vorschlägen (Glühbirne).
  • Typwechsel per Icon oder Kontextmenü Type (Ctrl+Menü); bei Mehrfachauswahl Rückfrage (Einstellung Always/Never/Ask).
  • Suchen/Ersetzen (Ctrl+F/H) mit Groß/Klein, ganzes Wort, Regex, nur Auswahl; Treffer orange.
  • Entities über die Eingabehilfe „Entities“ einfügen; XInclude, Dateipfad und Base16/Base64-kodierte Dateien über Insert.

Neue Knoten entstehen immer leer als Element und werden danach umgetypt oder benannt. Die Eingabehilfen (Siblings, Children, Values) reagieren auf die markierte Zelle: sie zeigen nur, was das Schema an dieser Stelle zulässt, und Values listet Enumerationswerte zum Doppelklick.

8. Filter, Formeln, Bilder, Diagramme

Quelle: Filters, Formulas (XML), Images, Charts, Screenshots Filter, Formel, Formelspalte

FeatureDetails
FilterXQuery-3.1-Ausdruck auf einem Elementknoten (Kontext = dieser Knoten), zeigt nur die passenden Nachfahren. Rechtsklick › Filter, Ausdruck eingeben, Trichter-Icon schaltet an/aus, Doppelklick editiert. Filter sind nestbar (innerer Filter arbeitet auf dem Ergebnis des äußeren), ändern nur die Anzeige und werden in einer Metadatei (json-metadata.json unter Altova\XMLSpyCommon) gespeichert, nicht im Dokument. Filter to Focus erzeugt einen Filter auf der Wurzel, der nur den markierten Knoten mit Nachfahren zeigt.
FormelnKnotentyp Formula: Name, XQuery-3.1-Ausdruck (Kontext = Elternknoten), Ergebnis darunter. Diskettensymbol speichert das Ergebnis als Elementinhalt im Dokument; Einstellung Persistence (Default an) legt den Ausdruck zusätzlich als Processing Instruction ab. Ergebnisse werden immer in der Metadatei gehalten. In Tabellen erscheint eine spaltenweit gleiche Formel im Kopf; einzelne Zellen können abweichen, wenn man die Tabellendarstellung kurz abschaltet.
BilderBase64-Inhalt wird als Grafik gerendert (PNG, JPEG, BMP, GIF, SVG). Einfügen über Edit › Insert › Encoded External File (Pfad, Base64, als neues Kindelement möglich) oder per Formel unparsed-text("url", "x-binarytobase64"). Save as Image schreibt die Grafik zurück in eine Datei; die Endung wird aus den Daten erkannt. Bilder aus Bildeditoren lassen sich direkt einfügen.
DiagrammeFormel mit der Altova-Erweiterung altovaext:chart(config, series): Konfiguration (title, kind, width, height), Serien als Arrays (Name, X-Werte, Y-Werte). Das Diagramm erscheint als Bild unter der Formel und kann als Bild oder XML kopiert werden.

9. Navigation und Fenster

Quelle: Split View, Screenshot Scroll-Header

  • Split View: horizontales Teilen durch Ziehen des Split-Icons oben rechts, vertikales durch das Icon unten rechts. Beide Hälften scrollen und navigieren unabhängig, zeigen aber dasselbe Dokument; Edits erscheinen sofort in beiden. Doppelklick auf den Splitter beendet die Teilung. Jedes Dokument hat seinen eigenen Split-Zustand.
  • Nummerierung: gleichnamige Geschwister werden ab 1 durchnummeriert (<1>, <2>), die Nummern sind reine Anzeige und bleiben bei Filtern stabil.
  • Markierung bleibt beim Wechsel in die Textansicht erhalten; der Wechsel aus der Textansicht prüft zuerst die Wohlgeformtheit.
  • Copy XPath (Ctrl+Shift+C) und Copy XPointer liefern den Pfad des markierten Knotens.
